# LiveLabs YC RFS Validator

Use this to stress-test LiveLabs ideas against the current YC Requests for Startups without pretending RFS is a checklist. YC explicitly says RFS is extra validation, not a requirement to apply.

If the user asks for "latest/current" YC RFS, browse `https://www.ycombinator.com/rfs` first and update the reference summary before judging.

## Validation Lenses

Score the idea on:

1. **RFS theme fit**: Which current YC RFS theme does this map to, if any?
2. **AI-native depth**: Is AI foundational to the workflow/business model, or just a feature?
3. **Workflow replacement**: Does it replace a service, workflow, interface, or software category rather than decorate it?
4. **Frontier timing**: What changed recently that makes this possible now?
5. **Founder-market fit**: Why LiveLabs specifically?
6. **Moat loop**: What data, distribution, operational workflow, or infrastructure compounds?
7. **Sharp wedge**: What is the narrowest YC-believable beachhead?
8. **Demo proof**: What would make the idea obvious in a 2-5 minute demo?

## Output

Use the template in `references/validation-template.md`. Be blunt. If the idea is weakly aligned, say so and propose a sharper framing.

Do not overfit the output to YC buzzwords. YC wants startups that make something people want; RFS themes are a lens, not the company.
